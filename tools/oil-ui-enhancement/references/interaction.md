# 交互、状态与反馈

## 先确定真实状态

对改变用户结果的对象列出 `初始 → 操作中 → 成功结果 / 可恢复错误`；按现有代码增加空数据、加载、部分加载、权限不足、过期或版本冲突。只覆盖真实可达分支，不制造状态组合。说明成功从哪个响应和后续读取确认。

| 对象 | 要观察的结果 | 容易漏掉的恢复 |
| --- | --- | --- |
| 表单 | 可见标签、字段错误、提交进度、服务端结果 | 失败保留输入；错误摘要可聚焦；重复提交只产生一次意图 |
| 弹窗/抽屉 | 进入前的焦点、标题、主要动作、关闭方式 | Escape；关闭回到发起处；有未保存内容时沿用产品约定 |
| 列表/搜索 | 当前条件、加载/空结果/错误、分页 | 过期响应不覆盖新查询；返回保留位置；多次加载不重复记录 |
| 收藏/参与/保存 | 以当前业务规则决定乐观或等待响应 | 失败回滚并说明；权限变化重新读取；状态名称保持准确 |
| 拖动排序 | 抓取对象、目标位置、落位结果 | 取消回原位；键盘移动或按钮替代；保存失败恢复 |
| 文件/上传 | 选择、校验、进度、完成、取消、失败 | 中止请求、重试；对象 URL 及时释放；本地预览不称上传成功 |

高频操作优先立即反馈，提交反馈由 pending 与结果区承担。不要为了播放动画延迟关键路径或暂时吞掉输入。禁用控件需要说明原因；能修复的错误就近给行动入口。

## 焦点与语义

导航用链接、动作用按钮；名称来自具体目的。现有无障碍组件优先，避免自己重写 dialog 焦点陷阱。使用原生 `dialog.showModal()` 时实测浏览器焦点、Escape 和关闭后恢复。抽屉若是模态须有同等处理，背景不可继续点击或获得焦点。

提示消息不能只短暂闪现或靠颜色传达。一般结果用 `role=status`，需要用户立即注意的错误使用合适的 alert；异步动画不反复播报。折叠按钮同步 `aria-expanded` 与 `aria-controls`，选项卡遵守键盘和选中语义。

## 中断与竞态

每次操作只有一个当前意图。使用 AbortController、请求标识或框架已有请求机制处理中止与迟到结果；在卸载时撤销监听、计时器与网络任务。关闭弹窗或切换对象后，旧请求不应让新对象跳到成功状态。

弹簧和布局过渡从当前视觉状态继续，不先跳回初始值。退出动画结束后再移除节点时，焦点与可点击区域必须同时符合当前状态，不能留下透明但可点击的层。
