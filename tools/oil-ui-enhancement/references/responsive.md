# 设备、触控与可访问性

以实际内容触发断点，不只按设备名换样式。手机优先确定主要任务、主要动作和导航；桌面再增加并列区域，二者共享对象、状态与权限。优先检查项目已有视口；没有约定时可从 390 × 844 手机及 1440 × 900 桌面开始，再检查 320px 窄屏和 200% 缩放。

- 正文以项目字号和中文阅读为准，普通正文对比度至少 4.5:1，大字至少 3:1。中文、长名字、长地点和大字号实测换行，不截断核心判断依据。
- 常用触控目标尽量达到 44 × 44 CSS px，密集控件保留间隔和清晰焦点。滚动、拖动之外提供可发现的替代操作；hover 不是唯一入口。
- 固定顶部/底部区域为内容预留空间，检查 `env(safe-area-inset-bottom)`、软键盘、横屏与弹窗高度。使用 `dvh` 前保留兼容回退；弹窗内容可滚动，主操作保持可达。
- 键盘从真实入口走完流程，焦点不被粘性栏遮挡；打开与关闭模态后，焦点恢复到仍存在的发起对象或合理位置。
- `prefers-reduced-motion` 在运行中变化时也生效。移除明显平移、缩放、视差和镜头移动，保留静态结果；必要进度用文本表达。不要把所有计时器设成零而破坏业务流程。
- 自动轮播、持续装饰和视频在离屏、后台或用户要求暂停时停止；用户仍能读到信息和主动操作。原产品明确需要的实时计时与状态刷新按业务规则继续，不因视觉暂停改写事实。
