# 学生课表识别对接

## 当前交付

“我的 → 我的课表”位于 `/v2/me?tab=timetable`。已实现图片选择与预览、加载与取消、按星期查看、课程详情和修正、结构化结果校验与本地存储。默认选中 Asia/Shanghai 当天星期。

2026-10-10 用户确认先完成前端交互、预留识别接口，演示数据明确标注。本次没有实现 OCR / AI 后端或云端个人课表存储。示例加载独立运行，不读取用户图片，不写入个人课表；退出或刷新后恢复个人数据。

## 预留请求（待后端确认和实现）

在 `.env.local` 设置 `VITE_TIMETABLE_RECOGNITION_PATH=/api/timetable/recognize`，重启开发服务或重新构建后生效。只允许同源 `/api/` 路径；需由服务端/部署代理提供该路由。仅配置环境变量不会自动生成后端服务。

- POST，`multipart/form-data`，文件字段 `image`，携带同源会话凭据。
- JPG、PNG、WebP，最大 10 MB。前端先检查格式、大小和是否能解码；后端仍须独立校验。
- 前端 60 秒超时，取消/离开时中止请求；即使迟到响应返回也不替换课表。
- 后端负责验证学生身份、处理本人的照片、限制请求频率、保护原图、执行识别。不得仅相信浏览器角色；识别服务密钥只能保存在后端。
- 无服务配置时不发送照片，也不返回伪造识别结果。401/403、413、非 JSON、空课表及无效课程返回明确失败，旧数据保留。

## 预留成功返回格式

```json
{
  "lessons": [
    {
      "name": "数据结构",
      "weekday": 1,
      "startTime": "09:00",
      "endTime": "10:50",
      "period": "第 1–2 节",
      "location": "T2-202",
      "teacher": "陈老师",
      "weeks": "1–16 周",
      "note": "",
      "needsReview": false
    }
  ]
}
```

名称和星期为必需。星期 1–7 对应周一至周日；时间为 24 小时 HH:mm，未知信息留空，不能用固定作息补造。最多 100 条，前端去除完全重复的课程。不同星期、时段、地点、老师或周次保留为不同安排。

缺少时间或后端未明确提供 `needsReview: false` 时标为待核对；缺少名称/星期、无效时间会拒绝整份结果。跨夜课程需后端分为两个实际星期的记录，不能传结束时间早于开始时间的单条课。不同周次的记录同样列出周次原文，本期不推算教学周。

有效结果自动替换本地个人课表，保留来源文件名和时间；原照片仅用于本次识别，前端不持久化。多账号、跨设备与后端留存策略须在正式后端接入时一并落实。

## 验证边界

`tests/timetable.test.ts` 验证时区、排序、去重、缺项、时间校验、修正、图片限制、取消及 HTTP 适配。HTTP 响应采用测试替身，不代表真实识别效果或后台验收。真实照片识别准确率需接入服务后另行验证。
