# 聊天安全与 iOS Release 配套交接

最终基线：`codex/ios-preview-backend-start` 的 `924a676`，已包含合并的课表照片识别 PR #2 及后续修复；本 PR 只新增聊天安全改动。无新增数据库迁移；目标服务仍须具备基线 migration 14。

## 行为

- `message.send` / `direct.send` 共用启用中的社区词库，先检查再写入；拒绝不产生消息或推送。
- `report.create {id,reason}` 支持收到的单条私信/当前有权访问的群消息，校验学生身份、成员/收件人资格，拒绝自己、无关、隐藏消息和重复待处理举报。
- 新举报保存 `privateMessage:true`、`targetKind`、`targetOwnerId`，证据只包含标题类型、该消息正文和创建时间。审核员不会获得整段聊天权限。
- `report.decide {id,upheld,reason}` 限审核员/超级管理员。成立后隐藏消息，聊天、会话预览、已读与尚未投递推送统一受控；通知结果并记录审计。
- 双向屏蔽覆盖群消息展示、已读、入队与投递；其他成员和本人消息不受影响，解除后恢复未被下架的历史。队伍结束通知仍投递，结束后的聊天排队通知取消。
- Web 私信/群聊都有消息举报和屏蔽；社区内容管理新增聊天举报队列。发送失败保留草稿和原因。iOS 配套 PR 提供同样入口及 Release HTTPS 地址门禁。

## 验证

- 全量 Vitest：105 文件、608 测试通过，含真实独立 PostgreSQL；新增双存储聊天权限、过滤、举报证据、去重、处理、屏蔽、注销依赖和推送复查。
- 独立 PostgreSQL 推送回归 31 项；注销回归 PostgreSQL 63 项、SQLite 48 项。
- 更新刚合并 OCR 后的独立注销测试契约：隐私政策现为 9 节并包含双语课表识别说明；测试清理先等待后台 GC 事务结束，再用独立连接删除随机 schema，避免清理死锁掩盖原始断言。
- Web/服务端类型检查、变更代码 ESLint、Web 构建通过；构建仍有原有大 chunk 提示。
- 本地浏览器：私信举报、关键词拒绝并保留草稿、屏蔽隐藏和禁发、审核员读取单条证据并判定成立。使用一次性内存 SQLite 账号。
- iOS 模拟器与 Release 构建详情见配套 iOS PR 文档。测试未使用真实 APNs 或生产服务。

## 合并后的配置和联调

1. 部署配套后端并确认运行 SHA、migration 14。当前改动不自动部署、不修改已有服务容器。
2. 在 `/v2/admin/keywords` 配置并启用实际运营词库；没有启用词条时不会凭空识别违规内容。本实现是关键词拦截，不宣称语义/图片审核。
3. 确保至少有审核员或超级管理员负责 `/v2/admin/moderation` 中的聊天举报；运营权限不能处理私聊证据。明确处理时限和运营轮值。
4. iOS 私有构建配置设置 `BNBU_API_URL` 为实际 HTTPS API origin，不能再靠 `BNBU_LOCAL_API_URL` 为 Release 配地址。
5. 两个真实测试账号在同群和私聊中验证过滤、举报、审核下架、双向屏蔽/解除、其他成员不受影响、未读及后台 APNs。已投递通知、离线缓存和网络刷新延迟需真机核对。
6. 注销回归确认本人/发送者删除后关联举报证据被清除；备份保留和恢复删除核查仍由部署运维落实。
