# Oil UI 本地增强入口

这是原创整合层，补充当前免费版的 UI 研发流程。上游参考文档及许可证在 `upstream/`，固定版本与文件校验值见 `sources.lock.json`。未获取或复制官方付费 Oil UI Pro 内容，也不声明功能或质量与其相同。

## 按任务读取

| 当前工作 | 读取 | 预期产物 |
| --- | --- | --- |
| 完整页面、表单、抽屉、弹窗、列表或消息状态 | [交互与状态](interaction.md) | 可达状态表、关键操作路径、错误恢复 |
| 手机、桌面、触屏与键盘适配 | [设备与可访问性](responsive.md) | 目标视口、焦点与触控方案 |
| 微交互、布局切换、拖动、列表进出 | [动效与选型](motion.md) | 目的、触发、结束、降级、代码清理 |
| 滚动场景、SVG、Canvas、WebGL 或特效 | [特效目录](effects.md) | 在现有库上的实现及性能边界 |
| 现有项目改版、组件打磨 | [改造与验证](verification.md) | 基线、最小修改、真实路径验证 |
| GitHub 参考与复用 | [来源索引](sources.md) | 版本、许可与按需文档路径 |
| 产品演示短片 | [OneTake 使用说明](onetake.md) | 独立视频制作任务，先核许可与运行依赖 |

对小改动只读影响区域的参考。用户明确要三套实际首屏时直接制作，不重复要求从文字选方向。首屏探索阶段不强加动效、交互或独立评审；用户选定后才扩展完整页面。

## 执行原则

1. 从用户任务、现有路由、数据来源与项目规则确定范围。纯视觉要求沿用已有权限、接口与业务状态。待确认业务含义不靠视觉默认值补全。
2. 每个动态对象先明确实际可达状态、真实结果与失败恢复，再决定如何动。动画的完成回调不代表业务写入成功。
3. 先复用项目现有组件、令牌、字体和依赖。按任务选择一个动效机制；一个元素的同一属性由一个机制控制。
4. 只在必要状态和目标设备上做检查。复杂交互验证保存结果、取消、失败、快速重复操作、返回和焦点。不能运行或观察的部分明确记录。
5. 新页面或完整改版初版稳定后，可派没有制作上下文、能看图的评审者检查一轮；主 Agent 验证发现后修正。阻塞实际使用的问题修复后复查；最多三轮，没有新证据不循环打分。普通局部修改由主 Agent 自查。

## 会同里项目适配

仅当当前任务处于 BNBU-Companion 或用户明确要求会同里时，核对根目录 `AGENTS.md` 与 `BUSINESS_RULES.md` 最新内容。字体、导航和数据模拟标识以当前已确认规则为准。未知体育进度保留未知，课表不推定到课，活动参与不推定正式报名。UI 展示和演示动画不产生学时、预约、审核或真实业务事实。

## 工具

- 保留原 Oil UI `scripts/build_explorer.py` 与 `scripts/shoot.mjs`，用于对比页与截图。
- `scripts/enhanced/search_reference.py <词语>` 可离线搜索已纳入文档；先看来源与范围，再按需读命中内容。只有参考文档的项目不调用其中未纳入的安装器或脚本。
- `assets/enhanced/motion-tokens.css` 是可选起点，已有令牌优先。
- `assets/enhanced/motion-lab.html` 是独立演示台，供检查焦点、失败恢复和减少动态；其中保存均为明确标识的模拟行为，不接业务 API。
