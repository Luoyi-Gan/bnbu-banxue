# BNBU 伴学学生 管理员 老师业务规则

业务角色分为学生、管理员、老师，每个角色分别定义属性、行为、关联对象和协作约束。超级管理员、审核员、运营是管理员内部的职责类型；体育老师是老师的资格类别。队长、成员、社团代表属于具体业务关系中的身份。AI 是自动业务执行能力，不作为第四种人员角色。

所有角色共用统一账号与身份验证规则。每个人具有唯一身份标识、姓名、所属组织、账号状态和已授权角色。同一个人可以具有多个已授权角色，各项行为按职责与对象归属判断，姓名不能替代唯一身份。

账号状态为正常、禁言或封禁。禁言限制发帖、评论和聊天；封禁限制全部业务写入，保留已有业务历史。身份认证不自动授予管理职责、体育老师资格或课程负责关系。

已确认规则具有约束力，文末待确认事项不产生默认授权。

## 一 学生

### 1 属性

| 属性类别 | 属性或关系 | 业务含义 |
| --- | --- | --- |
| 基本身份 | 唯一身份、姓名、学生身份、所属学院、账号状态 | 确定本人及其行为资格 |
| 认证 | 认证类型、组织、说明、审核状态与意见 | 表示身份声明的核实结果 |
| 课程 | 所属课程、任课老师、适用运动规则、已确认学时 | 决定运动提交范围及审核责任 |
| 预约 | 预约老师、原时段、拟改时段、状态 | 记录与老师之间的交流约定 |
| 组队 | 队伍、队长或成员身份、申请与处理结果 | 决定审批权和队伍交流资格 |
| 社团 | 代表关系、入驻申请、关注关系 | 代表可提交入驻，关注不构成会员资格 |
| 个人记录 | 活动访问、运动、内容、收藏、举报、反馈、消息与通知 | 记录实际行为及业务后果 |

业务关系和审核结果随真实行为产生，不能由学生任意声明为已通过、已加入或已获得学时。

### 2 能够做什么

| 行为 | 作用对象 | 条件与结果 |
| --- | --- | --- |
| 了解活动、访问官方报名地址 | 已发布活动 | 保存访问事实，外部主办方决定报名结果 |
| 了解公告 | 已发布公告 | 获取校园信息 |
| 预约、取消、接受或拒绝改期 | 本人 Coffee Chat 预约 | 满足时段、冲突与容量条件；只处理本人预约 |
| 开始、暂停、继续、结束、提交运动 | 本人所属课程和运动记录 | 依据课程规则提供凭证，等待负责老师审核 |
| 发帖、评论、点赞、收藏 | 社区内容 | 帖子评论须审核，收藏不改变公开资格 |
| 发起队伍、申请加入、交流 | 队伍及成员关系 | 按开放状态、容量和成员资格参与 |
| 同意或拒绝入队申请、结束队伍 | 本人担任队长的队伍 | 只在所属队伍内承担队长职责 |
| 关注社团、代表社团申请入驻 | 社团及入驻申请 | 审核通过才建立入驻记录 |
| 申请认证、举报、反馈回答 | 认证、举报和反馈 | 提供依据或理由并接收处理结果 |
| 参与会话、确认通知阅读 | 本人会话与通知 | 只处理本人具有关系的对象 |

### 3 与其他角色及对象互动

| 对方或对象 | 学生行为 | 对方处理与业务结果 |
| --- | --- | --- |
| 老师 | 预约开放时段、取消预约、接受或拒绝改期 | 老师管理本人时段，双方遵守同一最终约定 |
| 体育老师 | 提交所属课程的运动记录与凭证 | 负责老师审核，学生获得结果、原因与学时变化 |
| 管理员 | 提交认证、内容、举报、入驻与回答反馈 | 管理员按职责审核或处理，并通知相关人员 |
| 其他学生 | 组队申请、队长审批、共同交流 | 同意后形成成员关系，容量和队伍状态始终有效 |
| 学校活动与主办方 | 了解活动并使用官方报名渠道 | 平台记录访问，主办方处理实际报名 |
| 社团 | 关注或通过官方联系方式申请入会 | 关注关系与正式会员资格分别判断 |
| 校园知识回答 | 提问与反馈 | 已发布知识提供依据，管理员中的运营负责反馈处理 |

### 4 个人责任与权限边界

学生只能处理本人的预约和运动，不能审核本人运动或直接修改已确认学时。老师或管理员不能代学生接受改期。学生作为队长、社团代表时，相关权利只在具体队伍或社团关系中成立。

学生依据所属课程已发布规则开始运动，暂停不计时，结束后提供凭证和最多五百字说明。待审不计学时但占次数，通过才计学时，退回不计学时并释放次数。规则未发布或课程归属不明确时，不能套用其他课程规则。

### 5 内容与交流规则

学生提交帖子或评论后形成待审内容。帖子包括标题、分区和正文，评论关联具体帖子。既定长度上限为标题八十字、帖子正文一千字、评论三百字。

审核员或超级管理员可决定公开或隐藏。待审内容不作为向所有人公开的内容；作者可了解自己的审核状态。已公开内容可被有权人员下架，处置保留原因并通知作者；恢复也应留存处理原因。

学生可对公开内容表达点赞或收藏。收藏不改变内容公开资格；内容下架后，不因已被收藏而继续向无权人员提供。

私人会话只允许具有会话参与关系的人交流。队伍会话还受成员资格、队伍状态和用户状态约束。管理身份不提供私人会话查阅资格。群体通知不等于私人会话授权。

### 6 组队与成员规则

#### 1 队伍成立

学生可发起学习、娱乐或拼车队伍，提供类型相关的说明、约定时间、地点与容量，成为队长。创建队伍不生成其他人的申请、参与或回应。

队伍招募状态为开放或结束，公开状态与招募状态分别记录。隐藏队伍不等于自动结束队伍，结束也不抹去成员与申请历史。

#### 2 申请与审批

学生申请加入时，队伍必须开放、公开、有名额，且申请人未加入、没有同一队伍的待处理申请。申请成立后为待处理，不先占有成员身份。

队长决定同意或拒绝。同意前再次核对队伍状态与剩余容量；同意后才建立成员关系。不得通过多笔同时同意突破容量。拒绝不建立成员关系，并保留申请结果。

#### 3 结束与异常处置

队长可结束本人队伍。审核员或超级管理员可按异常处置职责下架、恢复、结束队伍或移除非队长成员，说明原因并通知受影响人员。

队伍被结束或下架后限制继续发送队伍消息；成员被移除后失去对应队伍交流资格。申请历史保留对象已下架等事实，不伪造其原审批结果。

### 7 社团关系规则

学生代表提交社团名称、介绍、类别和官方联系方式，形成待审申请。相同社团名称已待审或已通过时，不能重复申请。

审核员或超级管理员核对资料，通过后建立已入驻社团记录；驳回须说明原因并通知代表。运营维护已入驻社团的公开资料和联系方式。

社团入驻资格与公开状态是两个属性。下架须原因并通知代表，但不因此推断学校撤销该组织资格。学生只能关注已入驻且公开的社团；可取消本人关注。

入驻审核通过不自动赋予社团代表管理权限。学生通过官方联系方式申请加入社团，由社团决定会员资格。平台关注关系与外部入会结果分别理解。

### 8 认证与举报协作规则

#### 1 身份认证

申请人提交身份类型、学院或组织、申请说明。相同待审认证不能重复提交。审核员或超级管理员作通过或驳回决定，驳回须原因；撤销已通过认证也须原因并通知本人。

申请人声明身份 → 审核人员核实 → 形成认证结果。认证结果不直接授予体育老师资格、课程负责关系或管理角色。

#### 2 举报

学生对具体帖子、评论或队伍提出举报，说明理由。举报保存对象及提交时内容快照，同一学生对同一对象存在待处理举报时不得重复提交。

审核员或超级管理员决定举报成立或驳回。成立时执行对应对象下架；驳回时保留内容。处理结果通知举报人，实际处置另外通知作者或受影响人员。

举报不会立即证明违规，举报数量不能替代裁决。对象已变化时仍应记录处理时事实，不能伪造重复处置或删除原举报依据。

### 9 知识回答与反馈协作规则

运营维护知识正文、关键词、可信来源与发布状态。只有已发布知识可用于知识回答，回答须能够关联其来源。无匹配知识时不得编造学校决定、报名结果或个人事实。

学生对回答提出反馈时，保留问题、回答与说明。相同待处理反馈不重复产生。运营核对后记录处理结论，必要时修正知识，并通知反馈人。处理一条反馈不意味着所有相关知识自动有效。

## 二 管理员

### 1 属性

| 属性类别 | 属性或关系 | 业务含义 |
| --- | --- | --- |
| 基本身份 | 唯一身份、姓名、所属组织、账号状态 | 明确实际处理人 |
| 管理授权 | 职责类型、授权来源、启用状态 | 确定管理范围 |
| 职责类型 | 超级管理员、审核员、运营 | 管理员角色内部的职责划分 |
| 处理记录 | 对象、动作、时间、原因、结果和依据 | 追溯责任与业务变化 |

### 2 能够做什么

| 职责类型 | 可处理对象及行为 | 约束 |
| --- | --- | --- |
| 超级管理员 | 管理账号与角色，禁言、封禁、恢复；承担已明确的运营和审核职责 | 唯一超级管理员不可停用或降级，体育代审未授权 |
| 审核员 | 审核认证、帖子评论、举报、社团入驻；处理队伍异常 | 不能维护账号权限或执行未经授权的运营职责 |
| 运营 | 维护邮件活动、已入驻社团资料、老师交流资源、公告通知、知识反馈 | 无账号授权与禁言封禁权，不能代学生确认改期 |

审核员可对认证通过、驳回或撤销；对内容公开、隐藏或恢复；对举报判定成立或驳回；对社团入驻通过或驳回。队伍处置包括下架、恢复、结束、移除非队长成员。各项行为受状态、原因与通知要求约束。

运营可修正 AI 发布的活动、核实异常、下架与恢复活动，维护已入驻社团资料，协调老师时段和预约，发布公告与知识，处理学生反馈并投递通知。管理统计以实际业务记录为依据。

### 3 与其他角色及对象互动

| 对方或对象 | 管理员行为 | 对方获得的结果或约束 |
| --- | --- | --- |
| 学生 | 审核认证、内容、入驻，处理举报与反馈，实施账号限制或恢复 | 接收结果与原因，业务资格随有效决定变化 |
| 老师 | 运营协调资料、时段与预约 | 与老师处理同一对象，遵守冲突、容量和改期确认规则 |
| 学校邮件与 AI | AI 整理并自动发布，管理员核实异常和事后修正 | 学生获得有来源的活动事实；人工修正保留历史 |
| 社团与代表 | 审核入驻、维护公开资料、处理下架 | 代表接收结果；入驻不推断会员资格 |
| 队伍及成员 | 处理异常、结束或移除非队长成员 | 通知受影响人员，成员和交流资格同步变化 |
| 知识及反馈 | 维护来源、正文、发布情况，记录反馈处理结论 | 学生获得有依据的回答及处理结果 |
| 通知与审计 | 定向告知、核对投递与业务变化 | 不代用户已读，保留真实处理历史 |

### 4 权限边界

账号管理权不自动产生体育代审权。管理员不能代学生接受预约改期，也不能因管理身份查阅私人聊天。实际报名、入会、交流到场等外部结果没有依据时，不能由管理员推定。

学校邮件 AI 是自动执行能力，其自动发布职责不扩展为账号管理、运动审核或其他管理权限。管理员的事后修正不能被 AI 再次整理静默覆盖。

### 5 学校邮件 AI 与活动管理规则

#### 1 来源与处理责任

学校邮件是活动事实来源。AI 接收邮件信息并自动整理，满足发布条件即公开活动，不以运营事先批准为条件。运营或超级管理员在发布后检查并修正错误，对不适宜公开的活动执行下架。

邮件接收、AI 整理、活动发布是不同业务事实。收到邮件不代表处理成功，完成整理也不代表满足发布条件；失败不记录为已发布。非活动邮件不形成活动，原邮件中的行文要求不改变平台的业务授权规则。

#### 2 重要信息识别

| 信息 | 业务含义 | 识别约束 |
| --- | --- | --- |
| 标题与介绍 | 活动名称和内容摘要 | 可以重新组织语言，不改变原意，不增加邮件未说明的承诺 |
| 活动开始与结束时间 | 活动实际发生的时间范围 | 区分发信、收信、报名截止和活动日期；缺失结束时间不能擅定时长 |
| 报名截止时间 | 外部报名的截止条件 | 单独记录，不能替代活动发生时间 |
| 地点 | 活动实际举办地点或明确的线上形式 | 保留原文依据；多个地点需辨明用途，模糊位置不推断楼层或房间 |
| 主办方与参与条件 | 谁组织、谁可参与、有哪些限制 | 有依据才记录；未提及不等于面向所有人或免费 |
| 官方报名地址 | 原邮件提供的报名渠道 | 不自行生成或替换为无来源的报名地址 |

识别后的时间与地点是平台活动的正式业务属性，参与者基于这些属性了解实际安排。每项重要事实保留来源依据，AI 的语言整理和封面生成不能成为另一个事实来源。

自动发布仍要求标题、正文、有效起止时间、地点和官方报名地址完整。必要信息缺失、正文与附件冲突、多个时间地点无法辨明时保留为待核实，不能发布虚构的确定值。运营核实并补齐依据后可继续发布。此类异常处理不构成对所有邮件的人工预审。

#### 3 活动封面

封面有两种来源：邮件附件中与活动相关的图片，以及依据邮件内容生成的活动图片。AI 可采用附件图片，也可生成封面；运营或超级管理员可事后替换。两种来源的选择优先级未确定。

附件图片必须与本次活动对应，不能把无关附件当成活动封面。生成图片可以表达活动主题，但不证明活动已经发生、某人实际出席或存在某个真实场景。封面中的时间地点文字如与已核实活动属性冲突，应修正封面，不能反向修改活动事实去适配图片。

保留封面的附件来源或生成依据。图片取得或生成失败不等于文字信息识别失败；是否允许暂缺封面仍自动发布，另行确定。

#### 4 去重与处理状态

同一邮件重复接收或重新整理不得产生重复活动，相同主题和正文的重复邮件不重复发布。附件变化可能构成信息更新，不能仅因正文相同而忽略修订；修订邮件与原活动如何关联仍待确定。

沿用一封邮件对应一个活动记录。若一封邮件包含多个独立活动，先保留待核实，不擅自把不同活动的时间和地点混合；是否拆分为多项活动需另行确定。

| 处理阶段 | 行为人 | 条件与结果 |
| --- | --- | --- |
| 已接收 | 邮件活动 AI | 建立来源记录，开始识别 |
| 无活动信息 | 邮件活动 AI | 不生成活动，保留分类结果 |
| 待核实 | 邮件活动 AI 或运营 | 必要信息缺失、冲突或活动关系不明确，保留问题与依据 |
| 可发布 | 邮件活动 AI | 必要信息明确且符合发布条件，自动形成已发布活动 |
| 处理失败 | 邮件活动 AI | 保留失败原因；重试处理同一邮件，不创建重复活动 |
| 已发布后修正 | 运营或超级管理员 | 修正同一活动属性，保留修正历史 |

#### 5 事后修正

运营或超级管理员可修正标题、描述、时间、地点、报名信息和封面。修正须记录原值、新值、处理人、时间、原因与依据。涉及实际安排的修正应有学校邮件或经核实的来源，不以生成内容为依据。

修正后各参与者基于同一活动的新属性交流，地点变化后重新核对位置关系。AI 再次处理原邮件不得静默覆盖人工修正；新的识别结果与人工结论不一致时交由有权人员核实。已发布活动发现必要信息无法核实时，可先下架再处理。

活动时间地点修正后是否通知曾访问报名地址的学生、哪些修正应触发通知，仍待确定。已有的活动恢复通知规则继续有效。

#### 6 下架与恢复

运营或超级管理员下架活动必须说明原因。下架使活动停止公开，但保留原记录和访问历史。恢复学校邮件活动时须重新核对并说明原因；仅修改内容或由 AI 重新识别邮件不自动恢复发布。恢复后通知曾访问报名地址的学生，并保存处置记录。

地点变更后，原地点对应关系不能继续视为有效，应重新核对。缺少可信地点依据时不得作精确位置承诺。

#### 7 学校邮件与各参与者的交互

学校发送邮件 → AI 整理重要信息并选择或生成封面 → 符合条件自动发布 → 学生了解活动并访问学校官方报名地址 → 外部主办方处理报名。运营或超级管理员事后修正或下架活动；缺失和冲突信息由运营核实。

平台保存访问事实。访问次数按行为累计，独立访问人数按人去重；二者均不能解释为实际报名人数。学生自行发起平台活动、站内报名审批、候补和票券不属于已确认范围。

运营发布公告，维护正文、分类与重要程度。公告发布和定向通知属于不同业务；不能以公告存在推断所有学生已经收到或阅读。

### 6 通知与审计规则

#### 1 业务事件与接收关系

| 事件 | 应获得结果的人 | 结果含义 |
| --- | --- | --- |
| 预约成立 | 预约学生、所属教师 | 同一预约建立 |
| 预约取消 | 预约学生、所属教师 | 原预约失效，名额释放 |
| 改期提出 | 预约学生 | 等待本人接受或拒绝 |
| 改期接受或拒绝 | 预约学生、所属教师 | 最终约定时间明确 |
| 运动审核通过或退回 | 记录所属学生 | 同一审核结论、原因及学时后果 |
| 认证或入驻审核 | 申请人或社团代表 | 申请结果与原因 |
| 内容或队伍处置 | 作者、受影响成员等 | 限制变化及原因 |
| 举报处理 | 举报人 | 举报结论；不扩展私人资料访问资格 |
| 活动恢复 | 曾访问该活动报名地址的用户 | 活动恢复公开 |
| 回答反馈处理 | 反馈人 | 处理结论 |
| 禁言、封禁或恢复 | 被处理人 | 限制或恢复情况与原因 |

定向通知必须确定接收人。每个人只能确认本人的阅读状态；不能以一人已读推断整批已读。阅读率为该批已读通知数量除以成功产生的通知数量，分母为零时不形成有效阅读率。

通知失败不推翻已经成立的预约或审核，不得靠重复办理业务来补发通知。通知送达和通知已读分别代表不同事实。

#### 2 审计

授权、审核、发布、下架、恢复、改期、管理取消、禁言封禁等行为应保留行为人、职责身份、对象、时间、理由和结果。操作失败不能记成成功；后来恢复不能覆盖先前处置历史。

审计用于核对责任与事实，不因此赋予管理人员额外的私人信息访问资格。

## 三 老师

### 1 属性

| 属性类别 | 属性或关系 | 业务含义 |
| --- | --- | --- |
| 基本身份 | 唯一身份、姓名、所属学院、老师身份、账号状态 | 确定老师本人及行为资格 |
| 交流资料 | 介绍、研究领域、交流主题、交流地点 | 帮助学生了解交流内容 |
| 交流资源 | 本人时段、容量、开放状态、预约与拟改期 | 决定可预约安排和已建立的约定 |
| 体育资格 | 是否具备有效体育老师资格、资格来源 | 决定体育管理资格，不能自行声明后生效 |
| 课程负责关系 | 负责课程、学期、课程学生与适用规则 | 确定体育管理与审核的具体范围 |
| 审核历史 | 运动记录、决定、原因、处理时间 | 追溯课程审核责任 |

普通老师和体育老师均属于老师角色。体育资格与课程负责关系必须同时成立，才能管理相应课程；有体育资格但没有课程，不产生对其他课程的权限。

### 2 能够做什么

| 行为 | 普通老师 | 体育老师 | 对象与条件 |
| --- | --- | --- | --- |
| 管理本人 Coffee Chat 时段 | 可以 | 可以 | 不重叠、容量有效；已有预约不能直接改时间或关闭 |
| 了解本人被预约情况 | 可以 | 可以 | 仅限本人交流业务需要的学生信息 |
| 提出改期或取消预约 | 可以 | 可以 | 说明原因，改期由预约学生决定 |
| 管理体育课程规则 | 不可以 | 可以 | 仅本人负责课程；创建与分配机制待确认 |
| 审核运动记录 | 不可以 | 可以 | 仅本人负责课程的待审记录，退回须原因 |
| 核对课程学时 | 不可以 | 可以 | 依据有效审核结果，不能随意改写学时 |
| 接收并确认本人通知 | 可以 | 可以 | 仅限本人接收关系 |

### 3 与其他角色及对象互动

| 对方或对象 | 老师行为 | 对方处理与业务结果 |
| --- | --- | --- |
| 预约学生 | 提供时段，了解预约，提出改期或取消 | 学生满足条件即预约成功；接受或拒绝改期后形成最终约定 |
| 课程学生 | 体育老师明确运动规则，审核提交的证据 | 学生按规则运动，通过计学时，退回获得原因 |
| 管理员 | 由运营协助协调交流资源与预约 | 修改同一对象，不绕过名额和确认规则 |
| 交流时段及预约 | 维护本人资源和占用关系 | 成立占用，取消释放，待改期保留原占用并预留新名额 |
| 体育课程及运动记录 | 根据体育资格和负责关系管理 | 普通老师及无负责关系的老师不能审批 |
| 通知 | 接收预约变化与相关业务结果 | 阅读状态仅代表本人 |

### 4 权限边界

老师不能自行授予管理角色或体育资格，不能代学生接受改期。师生关系不授予学生全部校园行为、其他课程记录或私人聊天的访问资格。

学生预约条件满足即成立，无需老师逐笔批准。预约时间结束不证明交流已完成；学生提交运动不代表学时已通过。管理员代审、运动复核和课程分配的未确认事项不产生默认权利。

### 5 Coffee Chat 与学生协作规则

#### 1 教师和时段

教师维护本人的交流时段，运营可协调维护教师资料与交流资源。教师资料包含姓名、学院、介绍、研究领域、交流主题和地点。

时段开始时间须早于结束时间，容量为正整数，同一教师开放时段不能重叠。学生不能预约已开始、关闭、不可用或所属教师已停止提供的时段。容量不能低于当前占用，包括拟改期预留。

时段已有有效预约或改期预留时，不能直接改变教师、调整时间或关闭时段；先处理受影响预约。教师仍有有效预约时不能直接停止其交流服务。

固定三十分钟和固定一对一尚未确认为所有时段的规则，时长和容量以已确定的时段条件为准。

#### 2 预约建立与取消

学生选择一位教师的有效时段提出预约。成立条件为时段有名额、本人没有重复预约、本人已有预约与拟改期时段不造成时间冲突，且本人具备业务行为资格。

条件满足即建立“已预约”记录，占用一个名额，并通知预约学生和所属教师。教师不需要再次批准预约。

学生可取消本人预约；教师可取消本人的被预约记录；运营或超级管理员可按协调职责取消。教师和管理人员取消须填写原因。取消后释放占用、保留取消记录，并通知相关人员。

#### 3 改期状态与名额

| 原状态 | 行为人及行为 | 成立条件 | 结果 |
| --- | --- | --- | --- |
| 已预约 | 所属教师或有权运营提出改期 | 新时段属于同一教师、不同于原时段、有效、有容量、无学生时间冲突，并说明原因 | 改期待确认；保留原占用并预留新名额 |
| 改期待确认 | 预约学生接受 | 新时段仍有效，当前请求尚未处理 | 改为新时段的已预约；释放原占用 |
| 改期待确认 | 预约学生拒绝 | 当前请求尚未处理 | 恢复原时段的已预约；释放新预留 |
| 已预约 | 有权人员取消 | 预约尚未取消；管理取消符合原因要求 | 已取消；释放原占用 |
| 改期待确认 | 有权人员取消 | 预约尚未取消；管理取消符合原因要求 | 已取消；释放原占用与新预留 |
| 已取消 | 重复取消或提出改期 | 不成立 | 不改变记录，不产生额外释放 |

只有预约学生可以接受或拒绝改期，教师和管理人员不能代为确认。同一预约同时最多有一个待确认改期。新时段失效后不能接受该改期，需拒绝或由相关人员重新协调。

改期待确认仍计为一笔预约，但原、新时段分别占用一个名额。时段结束不证明学生已经到场或交流完成。自动超时、取消截止、爽约与评价规则待确认。

### 6 体育课程与学生运动审核规则

#### 1 课程管理资格

只有体育老师可以承担已确认的体育课程管理和运动审核职责，且必须对具体课程具有负责关系。普通教师没有体育管理资格；体育老师甲不能管理或审核体育老师乙的课程，除非另有有效负责关系。

体育老师管理课程名称、学期、目标学时与运动规则。课程必须明确负责教师和学生归属。教师资格来源、课程创建权分配、学生关系分配方式及多人任课规则仍待确认。

#### 2 课程规则

学生依其所属课程的已发布规则参加运动。规则至少明确最低时长、单次最多计入时长、每日和每周次数上限及允许项目。最低时长须为正数且不大于最多计入时长，次数为正整数。

规则未发布或学生课程归属未明确时，不得用其他课程或示例条件替代。历史示例中的学时和次数不自动成为正式课程标准。

规则变更应明确旧运动适用何种条件；追溯调整、版本生效和课程归档后的处理尚待确认。未确认前不能用新规则重算既有审核结果。

#### 3 学生运动行为

1. 学生具备有效课程成员关系且课程规则已发布，选择允许项目开始运动。
2. 开始前检查未完成运动和次数约束；已有未完成运动需先处理，不同时创建另一条活动中的运动过程。
3. 学生可暂停和继续运动；暂停期间不累计有效时长。结束时确定本次有效时长。
4. 学生提供运动凭证和说明，符合最低时长与材料要求后提交待审。
5. 本次可计入时长不得超过课程规定的单次上限；不足最低时长不能提交有效申请。
6. 提交后产生属于学生与课程的同一条待审记录，交由有负责关系的体育老师审核。
7. 学生可以放弃未提交运动，放弃不形成待审记录或学时。

运动凭证和说明是审核依据，凭证须为运动图片，说明不超过五百字。

#### 4 审核决定与学时

| 当前状态 | 行为人 | 行为与条件 | 业务后果 |
| --- | --- | --- | --- |
| 运动中 | 本人学生 | 暂停 | 停止累计有效时长 |
| 已暂停 | 本人学生 | 继续 | 恢复累计有效时长 |
| 运动中或已暂停 | 本人学生 | 结束 | 固定本次计时结果，等待材料与提交 |
| 已结束未提交 | 本人学生 | 满足时长、材料、课程与次数条件后提交 | 产生待审核记录，暂不增加学时 |
| 待审核 | 负责该课程的体育老师 | 核对课程、学生、时长、项目、凭证与说明后通过 | 保存审核人和时间，计入允许时长，通知学生 |
| 待审核 | 负责该课程的体育老师 | 填写具体原因后退回 | 不增加学时，释放次数占用，通知学生 |
| 已通过或已退回 | 任意人员 | 重复作原审核决定 | 不成立，不重复计时或通知为新决定 |

审核决定应记录审核人、时间、结果和原因。学生不能审核本人记录。普通教师、无课程关系的体育老师及未经授权的管理人员不能审核。

课程累计学时由有来源的历史学时与审核通过记录组成，同一记录最多计入一次。待审和退回记录不计入学时；只改变记录描述不能改变已确认学时。

#### 5 次数与时间

待审和通过记录占用课程允许次数，退回不占用。日期归属以该次运动开始时间计算，自然日与周一开始的自然周使用上海时区。暂停、继续、重复提交不能产生新的次数额度。

退回后既定处理为重新记录符合规则的运动。补充材料、申诉、撤销通过、重新审核、管理人员代审及学时追溯调整都须另行确认。

#### 6 体育老师与学生的交互

体育老师明确课程规则 → 有课程关系的学生按规则运动并提交证据 → 负责老师审查 → 通过则计入学时，退回则说明原因 → 学生获得同一审核结果。

教师只获得处理该课程所需的学生资料，不因任课关系获得学生全部校园行为或其他课程记录。

## 共同业务约束

1. 行为必须同时满足有效身份、相应角色、对象归属、当前状态和业务条件；仅知道对象标识不形成访问或处理资格。
2. 学生只能提交或处理本人的个人申请、预约、运动记录和通知；队长职责按所属队伍另外判断。
3. 教师只能管理本人的交流资源；体育老师同时受到课程负责关系限制。
4. 管理角色按职责处理业务，审核员不能维护账号权限，运营不能实施禁言封禁。
5. 身份或授权撤销后，后续行为按新权限判断；之前的合法处理保留行为人与历史结果。
6. 管理身份不授予私人聊天查阅权；教师身份也不授予学生私人聊天查阅权。
7. 同一事实在不同参与者之间保持一致。例如一笔预约的状态、一条运动记录的审核结果只有一个业务含义。
8. 行为未成功时不产生成功结果；重复处理不能增加预约数量、名额占用或学时。
9. 下架、恢复、认证撤销、管理取消、退回、禁言和封禁等处置按各自规则保留原因，并通知受影响人员。
10. 待确认事项不产生权限、状态或自动处理规则。

## 关联业务对象的属性

| 对象 | 主要业务属性 | 归属与关系 |
| --- | --- | --- |
| 授权 | 授权对象、角色、有效状态、授权来源 | 属于某个人，确定可承担职责 |
| 身份认证申请 | 申请人、身份类型、组织、说明、状态、审核意见、审核时间 | 审核员处理；与管理授权独立 |
| 学校邮件 | 邮件标识、主题、发件方、活动相关正文、收取时间、附件图片、识别结果、处理状态 | AI 处理来源，一封邮件对应一个活动记录 |
| 活动信息识别结果 | 字段名称、识别值、原文或附件依据、歧义与缺失情况、处理时间 | 属于来源邮件，用于形成活动事实 |
| 活动 | 标题、介绍、类别、实际起止时间、地点、主办方、参与条件、报名截止时间、来源邮件、官方报名地址、封面、发布状态 | AI 自动发布，运营或超级管理员事后修正；部分属性可因来源未提供而为空 |
| 活动封面 | 图片、来源类型、关联邮件附件或生成所依据内容、选用记录 | 来源为相关附件图片或依据邮件生成的图片 |
| 活动修正记录 | 活动、修正人、时间、字段、原值、新值、原因、依据 | 保留自动整理结果和后续人工修正关系 |
| 活动访问记录 | 活动、访问人、访问时间、访问地址 | 表示访问行为，不表示报名结果 |
| 公告 | 标题、正文、分类、发布人、发布时间、重要程度 | 运营维护，供授权接收者了解校园信息 |
| 教师交流时段 | 所属教师、开始时间、结束时间、容量、开放状态 | 由本人教师维护，运营协调 |
| 教师交流预约 | 预约学生、教师、原时段、拟改时段、状态、原因、建立时间 | 学生、所属教师与有权运营处理同一预约 |
| 体育课程 | 名称、学期、负责教师、课程学生、目标学时、运动规则、规则发布情况 | 体育老师依据负责关系管理 |
| 运动规则 | 最低时长、单次最多计入时长、每日和每周次数上限、允许项目 | 属于具体课程，不推定所有课程一致 |
| 运动过程 | 学生、课程、项目、开始时间、有效时长、暂停情况、结束情况 | 属于本人及对应课程 |
| 运动记录 | 学生、课程、项目、时间、有效时长、可计入时长、凭证、说明、审核结果和原因 | 由负责该课程的体育老师审核 |

| 举报 | 举报人、对象、对象内容快照、理由、状态、处理人、结论和时间 | 保留提交时事实，审核员裁决 |

| 通知 | 接收人、业务对象、事件、正文、产生时间、阅读状态 | 每位接收人的阅读状态独立 |
| 审计记录 | 行为人、所用身份、动作、对象、时间、原因、结果 | 用于追溯已发生的业务处理 |
