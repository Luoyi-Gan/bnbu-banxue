# 03 校园窗口 · 完整首页预览

用户确认：`01：选 03 校园窗口`。沿用首轮C的不对称校园照片、竖排文楷问候、天空蓝强调和下一项安排优先，深化完整首页。继续遵守“先不要替换当前页面”的范围，开发预览地址：

http://127.0.0.1:4174/v2/design/campus-window

当前首页仍为 `/v2`；预览顶部有返回当前首页的入口。预览路由沿用现有学生身份检查，只在存在Vite热更新上下文时注册，生产构建不注册此路由。使用 `Boolean(import.meta.hot)` 与项目已有本地预览入口保持一致；当前服务的NODE_ENV导致`import.meta.env.DEV`为false，因此不以这个字段判断预览。

## 设计与内容

- 顶部保留搜索、通知与个人设置；手机课表窗口入口在预览顶栏显示为日历图标，避免遮挡体育数据。
- 校园窗口复用三张校园照片。日期中的月、日数字在竖排中组合显示；问候和昵称使用既有文楷，正文、时间和状态使用MiSans。
- 主卡读取现有 `liveStudentSchedule()` 第一项，链接直接打开对应活动、Coffee Chat或队伍；下一行读取第二项。没有安排、读取中和读取失败均有实际状态与行动入口。
- 今日安排、未读通知和体育进度复用当前账号的现有摘要规则；未知值保留“—”，尚未入班有独立说明，不推定到课、正式报名或学时事实。
- 下方依次呈现最多两项未结束的活动推荐、校园服务与AI入口、校园动态、组织关注和校园探索入口。复用现有详情、收藏、关注与错误反馈。
- 桌面使用更大的校园画面与并列内容；手机保持单列阅读和已有五项导航。完整页面按真实文字自适应，不再固定844px高度。
- 本地验收数据保留页面标识和全局模拟提示；没有创建新账号或重新注入数据。

## 动效与减法

照片650ms淡入切换、主卡280ms轻进入、箭头160ms微反馈；手动选图暂停自动切换，提供播放/暂停。照片轮播在减少动态、离屏及后台时停止更新。系统减少动态偏好在运行中切换也生效，移除位移与切换过渡，保留内容与操作。

首轮的照片口号未加入完整首页，页面以真实安排为主。独立评审后将动态标题改为两行，并降低手机组织封面的高度；保留对象名称、状态与操作。

- 实际进入下一项安排详情并返回；搜索焦点与Escape、现有课表窗口可用。
- 收藏操作经过真实本地API，刷新后读回；模拟提交失败时维持原状态。脚本结束时恢复原始验收关系。
- 空数据、未知体育进度、读取失败和重试恢复使用浏览器层响应，不修改数据库中的业务对象。

- 一轮没有制作上下文的独立视觉评审，未发现阻碍使用的问题。已采纳动态标题、竖排数字和组织区留白三项建议；主Agent复查后运行浏览器回归。
