# BNBU 伴学业务规则与身份协作

本规则定义参与者、身份属性、业务对象、允许行为、状态变化和协作关系。已确认规则具有约束力；标为待确认的事项尚未形成业务授权。

## 一 参与者与身份

### 1 共同身份属性

每个人具有唯一身份标识、姓名、所属组织、账号状态和已授权角色。同一个人可以具有多个已授权角色，各角色的职责和业务范围分别判断。姓名相同不代表同一个人。

身份验证确认行为人是谁；角色授权决定其可以承担什么职责；对象归属决定其可以处理哪些记录。三者不能互相替代。所有角色共用统一账号与身份验证规则，不因承担另一种职责而产生另一份个人业务历史。

账号状态包括正常、禁言、封禁。禁言限制发帖、评论和聊天；封禁限制全部业务写入。账号状态变更须保留原因并通知本人。封禁不意味着删除既有预约、申请、审核结果或历史记录。

身份认证用于证明申请人所声明的学生、社团代表或官方机构身份，认证通过不自动产生教师、体育老师或管理权限。

### 2 人员类型与职责

| 人员类型 | 专有属性或关系 | 允许承担的行为 | 约束范围 |
| --- | --- | --- | --- |
| 学生 | 学生身份、所属学院、课程成员关系、个人参与记录 | 了解活动、预约教师、提交运动、交流、组队、关注社团、申请认证、举报、反馈 | 本人记录及具有参与资格的业务 |
| 普通教师 | 教师身份、所属学院、研究领域、交流主题、公开介绍、交流地点 | 管理本人 Coffee Chat 时段和预约，提出改期或取消预约 | 本人的交流资源与预约；无体育管理权限 |
| 体育老师 | 教师共同属性、体育老师资格、负责课程关系 | 教师共同职责，以及管理负责课程和审核运动记录 | 仅本人负责课程及该课程学生的相关记录 |
| 超级管理员 | 唯一超级管理员身份 | 管理账号和角色，禁言、封禁、恢复用户；承担已明确的运营与审核职责 | 唯一身份不可停用或降级；体育代审权限未确定 |
| 审核员 | 审核角色、角色启用状态 | 处理身份认证、内容、举报、社团入驻与队伍异常 | 与审核职责有关的对象 |
| 运营人员 | 运营角色、角色启用状态 | 维护邮件活动、社团资料、教师交流资源、公告、通知、知识与反馈 | 已明确的运营业务；无账号授权和禁言封禁权 |

体育老师是教师的一种资格，不是所有教师共有的职责。具备体育老师资格但没有负责课程关系时，不因此获得其他课程的管理权。普通教师不能因处理 Coffee Chat 预约而获得学生运动记录的访问权。

### 3 随业务关系产生的身份

| 关系身份 | 形成条件 | 行为与责任 |
| --- | --- | --- |
| 队长 | 发起并拥有队伍 | 核对入队申请、同意或拒绝、结束本人队伍 |
| 队伍成员 | 经同意加入队伍 | 参与所属队伍交流，遵守队伍状态和成员限制 |
| 入队申请人 | 向开放队伍申请加入 | 等待队长决定；申请不等于成员资格 |
| 社团代表 | 代表社团提交入驻资料 | 提供名称、介绍、类别和官方联系方式，接收审核与处置结果 |
| 社团关注者 | 关注已入驻且可见的社团 | 维持或取消关注；关注不等于入会 |
| 预约学生 | 成功预约教师交流 | 遵守约定，取消本人预约，接受或拒绝改期 |
| 课程学生 | 与课程建立有效成员关系 | 按课程规则提交本人运动记录 |
| 内容作者 | 提交帖子或评论 | 对内容负责，接收审核和处置结果 |
| 举报人 | 对具体对象提出举报 | 提供理由，接收处理结果；无自行裁决权 |

这些身份只在具体关系中成立。队长不能审批其他队伍的成员，社团代表不能审核本人的入驻申请，举报人不能以举报为由获取他人的私人信息。

### 4 外部参与方

学校邮件提供活动来源。学校或活动主办方通过其官方渠道处理实际活动报名；社团通过官方联系方式处理实际入会。平台记录所掌握的业务事实，不推断外部报名成功、正式会员资格、活动出席或教师交流到场情况。

学校身份、课程和学生关系的权威提供方尚待确定。教师资格不能由个人自行声明后直接生效。

## 二 业务对象与属性

| 对象 | 主要业务属性 | 归属与关系 |
| --- | --- | --- |
| 授权 | 授权对象、角色、有效状态、授权来源 | 属于某个人，确定可承担职责 |
| 身份认证申请 | 申请人、身份类型、组织、说明、状态、审核意见、审核时间 | 审核员处理；与管理授权独立 |
| 学校邮件 | 主题、发件方、活动相关正文、取得时间、候选活动信息 | 一封邮件对应一个活动草稿 |
| 活动 | 标题、介绍、类别、起止时间、地点、来源邮件、官方报名地址、发布状态 | 运营维护，学生了解与访问官方报名地址 |
| 活动访问记录 | 活动、访问人、访问时间、访问地址 | 表示访问行为，不表示报名结果 |
| 公告 | 标题、正文、分类、发布人、发布时间、重要程度 | 运营维护，供授权接收者了解校园信息 |
| 教师交流时段 | 所属教师、开始时间、结束时间、容量、开放状态 | 由本人教师维护，运营协调 |
| 教师交流预约 | 预约学生、教师、原时段、拟改时段、状态、原因、建立时间 | 学生、所属教师与有权运营处理同一预约 |
| 体育课程 | 名称、学期、负责教师、课程学生、目标学时、运动规则、规则发布情况 | 体育老师依据负责关系管理 |
| 运动规则 | 最低时长、单次最多计入时长、每日和每周次数上限、允许项目 | 属于具体课程，不推定所有课程一致 |
| 运动过程 | 学生、课程、项目、开始时间、有效时长、暂停情况、结束情况 | 属于本人及对应课程 |
| 运动记录 | 学生、课程、项目、时间、有效时长、可计入时长、凭证、说明、审核结果和原因 | 由负责该课程的体育老师审核 |
| 审核结果 | 处理对象、处理人、处理时间、决定、原因 | 关联原业务记录，不产生另一份事实 |
| 社团入驻申请 | 社团名称、介绍、类别、官方联系方式、代表、状态、审核意见 | 审核通过后建立社团目录记录 |
| 社团 | 名称、介绍、类别、代表、官方联系方式、入驻资格、公开状态 | 入驻资格与是否公开分别判断 |
| 关注关系 | 学生、社团、关注状态 | 不构成社团成员关系 |
| 队伍 | 队长、类型、说明、约定时间与地点、容量、成员、招募状态、公开状态 | 队长管理成员申请，审核员处理异常 |
| 入队申请 | 申请人、队伍、申请状态、处理结果 | 同意后才建立成员关系 |
| 帖子与评论 | 作者、正文、时间、审核状态；帖子另有标题和分区，评论关联帖子 | 作者提交，审核员决定公开或隐藏 |
| 会话与消息 | 参与人、发送人、内容、时间、会话所属关系 | 仅参与者有相应交流资格 |
| 举报 | 举报人、对象、对象内容快照、理由、状态、处理人、结论和时间 | 保留提交时事实，审核员裁决 |
| 知识条目 | 标题、正文、关键词、来源、发布状态 | 运营维护，已发布内容可用于回答 |
| 回答反馈 | 反馈人、问题与回答快照、反馈说明、状态、处理结果 | 运营处理并通知反馈人 |
| 通知 | 接收人、业务对象、事件、正文、产生时间、阅读状态 | 每位接收人的阅读状态独立 |
| 审计记录 | 行为人、所用身份、动作、对象、时间、原因、结果 | 用于追溯已发生的业务处理 |

## 三 身份授权和通用行为约束

1. 行为必须同时满足有效身份、相应角色、对象归属、当前状态和业务条件；仅知道对象标识不形成访问或处理资格。
2. 学生只能提交或处理本人的个人申请、预约、运动记录和通知；队长职责按所属队伍另外判断。
3. 教师只能管理本人的交流资源；体育老师同时受到课程负责关系限制。
4. 管理角色按职责处理业务，审核员不能维护账号权限，运营不能实施禁言封禁。
5. 身份或授权撤销后，后续行为按新权限判断；之前的合法处理保留行为人与历史结果。
6. 管理身份不授予私人聊天查阅权；教师身份也不授予学生私人聊天查阅权。
7. 同一事实在不同参与者之间保持一致。例如一笔预约的状态、一条运动记录的审核结果只有一个业务含义。
8. 行为未成功时不产生成功结果；重复处理不能增加预约数量、名额占用或学时。
9. 下架、恢复、认证撤销、管理取消、退回、禁言和封禁等处置按各自规则保留原因，并通知受影响人员。
10. 待确认事项不产生权限、状态或自动处理规则。

## 四 学校活动与公告

### 1 活动形成与发布

运营取得学校邮件，识别候选活动信息并核对。相同主题与正文不得重复形成活动；一封邮件对应一个草稿。存在多个日期或报名地址时，由运营核实其含义。

发布条件为标题、正文、有效起止时间、地点和官方报名地址完整。报名地址必须来自原邮件。活动地点只能表达已确认的空间范围；无法明确时保留待确认，不推断房间或楼层。

活动未发布时不作为公开活动。发布后学生可以了解活动并访问官方报名地址。学生自行发起平台活动、站内报名审批、候补和票券不属于已确认范围。

### 2 下架与恢复

运营下架活动必须说明原因。下架使活动停止公开，但保留原记录和访问历史。恢复学校邮件活动时须重新核对并说明原因；仅修改内容不自动恢复发布。恢复后通知曾访问报名地址的学生，并保存处置记录。

地点变更后，原地点对应关系不能继续视为有效，应重新核对。缺少可信地点依据时不得作精确位置承诺。

### 3 学生与运营的交互

运营发布活动 → 学生了解活动 → 学生访问学校官方报名地址 → 外部主办方处理报名。平台保存访问事实。访问次数按行为累计，独立访问人数按人去重；二者均不能解释为实际报名人数。

运营发布公告，维护正文、分类与重要程度。公告发布和定向通知属于不同业务；不能以公告存在推断所有学生已经收到或阅读。

## 五 Coffee Chat 交流预约

### 1 教师和时段

教师维护本人的交流时段，运营可协调维护教师资料与交流资源。教师资料包含姓名、学院、介绍、研究领域、交流主题和地点。

时段开始时间须早于结束时间，容量为正整数，同一教师开放时段不能重叠。学生不能预约已开始、关闭、不可用或所属教师已停止提供的时段。容量不能低于当前占用，包括拟改期预留。

时段已有有效预约或改期预留时，不能直接改变教师、调整时间或关闭时段；先处理受影响预约。教师仍有有效预约时不能直接停止其交流服务。

固定三十分钟和固定一对一尚未确认为所有时段的规则，时长和容量以已确定的时段条件为准。

### 2 预约建立与取消

学生选择一位教师的有效时段提出预约。成立条件为时段有名额、本人没有重复预约、本人已有预约与拟改期时段不造成时间冲突，且本人具备业务行为资格。

条件满足即建立“已预约”记录，占用一个名额，并通知预约学生和所属教师。教师不需要再次批准预约。

学生可取消本人预约；教师可取消本人的被预约记录；运营或超级管理员可按协调职责取消。教师和管理人员取消须填写原因。取消后释放占用、保留取消记录，并通知相关人员。

### 3 改期状态与名额

| 原状态 | 行为人及行为 | 成立条件 | 结果 |
| --- | --- | --- | --- |
| 已预约 | 所属教师或有权运营提出改期 | 新时段属于同一教师、不同于原时段、有效、有容量、无学生时间冲突，并说明原因 | 改期待确认；保留原占用并预留新名额 |
| 改期待确认 | 预约学生接受 | 新时段仍有效，当前请求尚未处理 | 改为新时段的已预约；释放原占用 |
| 改期待确认 | 预约学生拒绝 | 当前请求尚未处理 | 恢复原时段的已预约；释放新预留 |
| 已预约 | 有权人员取消 | 预约尚未取消；管理取消符合原因要求 | 已取消；释放原占用 |
| 改期待确认 | 有权人员取消 | 预约尚未取消；管理取消符合原因要求 | 已取消；释放原占用与新预留 |
| 已取消 | 重复取消或提出改期 | 不成立 | 不改变记录，不产生额外释放 |

只有预约学生可以接受或拒绝改期，教师和管理人员不能代为确认。同一预约同时最多有一个待确认改期。新时段失效后不能接受该改期，需拒绝或由相关人员重新协调。

改期待确认仍计为一笔预约，但原、新时段分别占用一个名额。时段结束不证明学生已经到场或交流完成。自动超时、取消截止、爽约与评价规则待确认。

## 六 体育课程与运动审核

### 1 课程管理资格

只有体育老师可以承担已确认的体育课程管理和运动审核职责，且必须对具体课程具有负责关系。普通教师没有体育管理资格；体育老师甲不能管理或审核体育老师乙的课程，除非另有有效负责关系。

体育老师管理课程名称、学期、目标学时与运动规则。课程必须明确负责教师和学生归属。教师资格来源、课程创建权分配、学生关系分配方式及多人任课规则仍待确认。

### 2 课程规则

学生依其所属课程的已发布规则参加运动。规则至少明确最低时长、单次最多计入时长、每日和每周次数上限及允许项目。最低时长须为正数且不大于最多计入时长，次数为正整数。

规则未发布或学生课程归属未明确时，不得用其他课程或示例条件替代。历史示例中的学时和次数不自动成为正式课程标准。

规则变更应明确旧运动适用何种条件；追溯调整、版本生效和课程归档后的处理尚待确认。未确认前不能用新规则重算既有审核结果。

### 3 学生运动行为

1. 学生具备有效课程成员关系且课程规则已发布，选择允许项目开始运动。
2. 开始前检查未完成运动和次数约束；已有未完成运动需先处理，不同时创建另一条活动中的运动过程。
3. 学生可暂停和继续运动；暂停期间不累计有效时长。结束时确定本次有效时长。
4. 学生提供运动凭证和说明，符合最低时长与材料要求后提交待审。
5. 本次可计入时长不得超过课程规定的单次上限；不足最低时长不能提交有效申请。
6. 提交后产生属于学生与课程的同一条待审记录，交由有负责关系的体育老师审核。
7. 学生可以放弃未提交运动，放弃不形成待审记录或学时。

运动凭证和说明是审核依据，凭证须为运动图片，说明不超过五百字。

### 4 审核决定与学时

| 当前状态 | 行为人 | 行为与条件 | 业务后果 |
| --- | --- | --- | --- |
| 运动中 | 本人学生 | 暂停 | 停止累计有效时长 |
| 已暂停 | 本人学生 | 继续 | 恢复累计有效时长 |
| 运动中或已暂停 | 本人学生 | 结束 | 固定本次计时结果，等待材料与提交 |
| 已结束未提交 | 本人学生 | 满足时长、材料、课程与次数条件后提交 | 产生待审核记录，暂不增加学时 |
| 待审核 | 负责该课程的体育老师 | 核对课程、学生、时长、项目、凭证与说明后通过 | 保存审核人和时间，计入允许时长，通知学生 |
| 待审核 | 负责该课程的体育老师 | 填写具体原因后退回 | 不增加学时，释放次数占用，通知学生 |
| 已通过或已退回 | 任意人员 | 重复作原审核决定 | 不成立，不重复计时或通知为新决定 |

审核决定应记录审核人、时间、结果和原因。学生不能审核本人记录。普通教师、无课程关系的体育老师及未经授权的管理人员不能审核。

课程累计学时由有来源的历史学时与审核通过记录组成，同一记录最多计入一次。待审和退回记录不计入学时；只改变记录描述不能改变已确认学时。

### 5 次数与时间

待审和通过记录占用课程允许次数，退回不占用。日期归属以该次运动开始时间计算，自然日与周一开始的自然周使用上海时区。暂停、继续、重复提交不能产生新的次数额度。

退回后既定处理为重新记录符合规则的运动。补充材料、申诉、撤销通过、重新审核、管理人员代审及学时追溯调整都须另行确认。

### 6 体育老师与学生的交互

体育老师明确课程规则 → 有课程关系的学生按规则运动并提交证据 → 负责老师审查 → 通过则计入学时，退回则说明原因 → 学生获得同一审核结果。

教师只获得处理该课程所需的学生资料，不因任课关系获得学生全部校园行为或其他课程记录。

## 七 社区内容与交流

学生提交帖子或评论后形成待审内容。帖子包括标题、分区和正文，评论关联具体帖子。既定长度上限为标题八十字、帖子正文一千字、评论三百字。

审核员或超级管理员可决定公开或隐藏。待审内容不作为向所有人公开的内容；作者可了解自己的审核状态。已公开内容可被有权人员下架，处置保留原因并通知作者；恢复也应留存处理原因。

学生可对公开内容表达点赞或收藏。收藏不改变内容公开资格；内容下架后，不因已被收藏而继续向无权人员提供。

私人会话只允许具有会话参与关系的人交流。队伍会话还受成员资格、队伍状态和用户状态约束。管理身份不提供私人会话查阅资格。群体通知不等于私人会话授权。

## 八 组队与成员关系

### 1 队伍成立

学生可发起学习、娱乐或拼车队伍，提供类型相关的说明、约定时间、地点与容量，成为队长。创建队伍不生成其他人的申请、参与或回应。

队伍招募状态为开放或结束，公开状态与招募状态分别记录。隐藏队伍不等于自动结束队伍，结束也不抹去成员与申请历史。

### 2 申请与审批

学生申请加入时，队伍必须开放、公开、有名额，且申请人未加入、没有同一队伍的待处理申请。申请成立后为待处理，不先占有成员身份。

队长决定同意或拒绝。同意前再次核对队伍状态与剩余容量；同意后才建立成员关系。不得通过多笔同时同意突破容量。拒绝不建立成员关系，并保留申请结果。

### 3 结束与异常处置

队长可结束本人队伍。审核员或超级管理员可按异常处置职责下架、恢复、结束队伍或移除非队长成员，说明原因并通知受影响人员。

队伍被结束或下架后限制继续发送队伍消息；成员被移除后失去对应队伍交流资格。申请历史保留对象已下架等事实，不伪造其原审批结果。

## 九 社团入驻与关注

学生代表提交社团名称、介绍、类别和官方联系方式，形成待审申请。相同社团名称已待审或已通过时，不能重复申请。

审核员或超级管理员核对资料，通过后建立已入驻社团记录；驳回须说明原因并通知代表。运营维护已入驻社团的公开资料和联系方式。

社团入驻资格与公开状态是两个属性。下架须原因并通知代表，但不因此推断学校撤销该组织资格。学生只能关注已入驻且公开的社团；可取消本人关注。

入驻审核通过不自动赋予社团代表管理权限。学生通过官方联系方式申请加入社团，由社团决定会员资格。平台关注关系与外部入会结果分别理解。

## 十 身份认证与举报

### 1 身份认证

申请人提交身份类型、学院或组织、申请说明。相同待审认证不能重复提交。审核员或超级管理员作通过或驳回决定，驳回须原因；撤销已通过认证也须原因并通知本人。

申请人声明身份 → 审核人员核实 → 形成认证结果。认证结果不直接授予体育老师资格、课程负责关系或管理角色。

### 2 举报

学生对具体帖子、评论或队伍提出举报，说明理由。举报保存对象及提交时内容快照，同一学生对同一对象存在待处理举报时不得重复提交。

审核员或超级管理员决定举报成立或驳回。成立时执行对应对象下架；驳回时保留内容。处理结果通知举报人，实际处置另外通知作者或受影响人员。

举报不会立即证明违规，举报数量不能替代裁决。对象已变化时仍应记录处理时事实，不能伪造重复处置或删除原举报依据。

## 十一 知识回答与反馈

运营维护知识正文、关键词、可信来源与发布状态。只有已发布知识可用于知识回答，回答须能够关联其来源。无匹配知识时不得编造学校决定、报名结果或个人事实。

学生对回答提出反馈时，保留问题、回答与说明。相同待处理反馈不重复产生。运营核对后记录处理结论，必要时修正知识，并通知反馈人。处理一条反馈不意味着所有相关知识自动有效。

## 十二 通知与审计

### 1 业务事件与接收关系

| 事件 | 应获得结果的人 | 结果含义 |
| --- | --- | --- |
| 预约成立 | 预约学生、所属教师 | 同一预约建立 |
| 预约取消 | 预约学生、所属教师 | 原预约失效，名额释放 |
| 改期提出 | 预约学生 | 等待本人接受或拒绝 |
| 改期接受或拒绝 | 预约学生、所属教师 | 最终约定时间明确 |
| 运动审核通过或退回 | 记录所属学生 | 同一审核结论、原因及学时后果 |
| 认证或入驻审核 | 申请人或社团代表 | 申请结果与原因 |
| 内容或队伍处置 | 作者、受影响成员等 | 限制变化及原因 |
| 举报处理 | 举报人 | 举报结论；不扩展私人资料访问资格 |
| 活动恢复 | 曾访问该活动报名地址的用户 | 活动恢复公开 |
| 回答反馈处理 | 反馈人 | 处理结论 |
| 禁言、封禁或恢复 | 被处理人 | 限制或恢复情况与原因 |

定向通知必须确定接收人。每个人只能确认本人的阅读状态；不能以一人已读推断整批已读。阅读率为该批已读通知数量除以成功产生的通知数量，分母为零时不形成有效阅读率。

通知失败不推翻已经成立的预约或审核，不得靠重复办理业务来补发通知。通知送达和通知已读分别代表不同事实。

### 2 审计

授权、审核、发布、下架、恢复、改期、管理取消、禁言封禁等行为应保留行为人、职责身份、对象、时间、理由和结果。操作失败不能记成成功；后来恢复不能覆盖先前处置历史。

审计用于核对责任与事实，不因此赋予管理人员额外的私人信息访问资格。

## 十三 身份间的协作边界

| 发起方 | 协作方 | 业务关系 | 最终决定权 |
| --- | --- | --- | --- |
| 学生 | 教师 | 预约教师已开放的交流时段 | 满足条件即成立；改期由学生确认 |
| 教师 | 预约学生 | 提出改期、说明取消 | 改期不能代学生同意 |
| 学生 | 体育老师 | 按课程规则提交运动事实 | 具有课程负责关系的体育老师审核 |
| 体育老师 | 课程学生 | 发布运动要求、解释审核结果 | 在本人负责课程范围内履职 |
| 学生 | 审核员 | 认证、内容、举报、社团申请 | 审核员按对应规则处理 |
| 队伍申请人 | 队长 | 申请成员资格 | 队长决定，但不能突破容量 |
| 社团代表 | 运营 | 维护已通过的社团资料 | 运营维护公开状态，不能推断外部会员资格 |
| 学生 | 运营 | 活动信息、回答反馈、预约协调 | 运营处理其职责内事务 |
| 教师 | 运营 | 共同维护教师交流业务 | 处理同一资源并遵守同一约束 |
| 用户 | 超级管理员 | 账号授权与行为限制 | 超级管理员按已确认管理职责处理 |

## 十四 待确认业务决策

| 事项 | 尚需明确的规则 |
| --- | --- |
| 身份和体育资格来源 | 谁证明学生、教师和体育老师身份；如何授予与撤销 |
| 课程与学生分配 | 谁创建课程、分配负责教师、建立或结束学生成员关系 |
| 多教师课程 | 是否允许共同任课、如何确定审核责任、如何交接 |
| 课程生命周期 | 何时可以开始接受运动、何时停止、停止后待审和进行中记录如何处理 |
| 规则变更 | 生效时间、旧运动适用规则及是否允许追溯 |
| 体育管理协调 | 管理人员是否可以查阅体育明细、代审、纠错或调整学时 |
| 运动复核 | 是否允许补材料、申诉、撤销通过和重新审核 |
| Coffee Chat 约束 | 是否统一固定时长、固定一对一、设置取消截止 |
| 改期时效 | 是否超时、超时后保留哪一约定、何时释放预留 |
| 交流结果 | 是否记录到场、完成、爽约和评价，以及由谁证明 |

未确认前，以上事项不产生默认权限和自动业务后果。
