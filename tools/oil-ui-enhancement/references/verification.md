# 存量改造、打磨与验证

## 从现有页面改

明确是视觉改版、流程修复还是新功能。只有视觉改版才探索整体风格；流程修复和新功能沿用项目视觉，除非用户另有要求。取当前页面、涉及状态和目标视口的基线，检查共享组件与令牌的调用范围；从根因修正，避免对同一问题连续追加 CSS 覆盖。

保留真实内容、路由、权限与可用操作。新增功能只实现当前授权范围。若业务数据无法取得，可在用户允许的独立原型中使用明确标识的模拟数据，并在交付中说明接入状态。

## 按影响验证

| 修改 | 验证重点 |
| --- | --- |
| 字号/间距/颜色等局部 | 目标区域与相邻元素、对比度与换行 |
| 新增进出或布局动效 | 正常、快速重复、反向中断、减少动态、卸载重进 |
| 弹窗/表单 | 键盘进入关闭、焦点恢复、失败保留输入、重复提交、恢复路径 |
| 保存/排序/收藏 | 真实成功响应、重新读取/刷新结果、失败恢复、权限/冲突分支 |
| 滚动/3D/复杂背景 | 正常与减少动态、离屏后台暂停、低性能回退、关键主体可见 |
| 完整页面 | 目标手机/桌面、窄屏与200%缩放、主要业务路径和错误恢复 |

跑与修改匹配的项目检查和仓库要求的测试；不为文档修改运行全量构建。动效有异步或竞态风险时围绕具体风险重复验证，不机械重复全部检查。浏览器模拟和本地样本只证明本地环境。

## 一次有效的评审

给评审者当前截图/录屏、用户任务、设备和约束，避免提供设计过程与期待结论。要求问题、可见证据、影响、具体修复建议；主观偏好标明，不把偏好列成故障。优先顺序：操作受阻/信息失真 → 可读性/焦点 → 空间与节奏 → 装饰。

主 Agent 自己确认问题并修正。复查受影响的状态；没有新问题就结束，不追求固定9分或宣称无缺陷。最多三轮，仍有差距时给出实际问题和边界。没有独立评审则写主 Agent 自检。

交付简要说明方向、具体修改、实际交互/动效、验证结果、未验证部分、可打开的预览和源码位置。用户只要探索首屏时在该阶段结束，不自动替换正式页面。
